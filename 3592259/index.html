Issue 3592259 / Walkthrough

Translate the interface text of code components

Components write their fixed labels with t() and formatPlural() from useTranslation(). Canvas finds the strings, Drupal lists them for translation, and every place that renders the component uses the translations: Drupal pages, Workbench previews, and headless frontends.

Seven short videos follow real Canvas Starter components, mainly the pricing table, through the code editor, Workbench, a content template, and a headless Next.js app, in Polish.

1 · Code editor · 50 seconds

Add, publish, and translate a label

A new label starts as t(''), which the editor reports with its line and column. Once it has text, the component is published, and the new string appears on Drupal's User interface translation page. After it is translated, the Polish page shows it with the other labels, including the plural "2 miesiące gratis".

2 · Code editor · 20 seconds

Publish with strings that cannot be determined

The editor does not block publishing for an invalid string. It sends the component without its strings, so Drupal treats them as unknown: this component falls back to its English source strings, while other components, like the header, stay translated. Locale keeps the existing translations for when the string is fixed.

3 · Workbench · 23 seconds

Preview Starter pages and mocks in Polish

Workbench lists the Drupal site's languages and previews pages, content templates, and component mocks with the site's translations. It only reads them, with the credentials Workbench already uses. The selected language is kept in the tab's session storage, per Drupal site, so it survives a reload of the tab, which also opens the mock with varied annual savings: all three Polish plural forms.

4 · Workbench · 11 seconds

Report a string that cannot be determined

navigation.tsx is saved with t('') outside the browser. Workbench updates the preview, names the file, line, and column, and shows the navigation in English until the file is fixed. A string that simply has no translation yet shows its source text, without a notice.

5 · Content template · 18 seconds

Translate a content template's interface text

The article template's body uses the Starter's prose component, which can show a reading-time plural. Workbench previews the template with a real article from Drupal, in English and then in Polish, and the Drupal-rendered Polish article shows the same label. The article content itself stays as authored. These articles are about 200 words long, so they all show the one-minute form.

6 · Headless Next.js · 44 seconds

Sync, translate, and render in a headless app

The Next.js app's copy of the pricing table adds one label. After the app is registered, opening a page syncs its components, and Drupal lists the new string. Once translated, Next.js renders it from page.context.translations, on the server and after hydration. TranslationsProvider can replace Drupal's translations with the app's own dictionary, or with null for the source strings.

7 · Headless build · 16 seconds

The build rejects an invalid string

Unlike the code editor, the Headless SDK fails the build for an invalid string, and reports its file, line, and column.

Notes

  • The code-editor videos publish once and then leave the editor. The known auto-save issue after publishing is not fixed by this change, and these videos do not exercise it.
  • Video 4 opens Workbench at localhost, a different host name from Drupal's 127.0.0.1. When it was recorded, translation lookups failed if Workbench and Drupal shared a host name and the browser was logged in to Drupal. That is now fixed: videos 3 and 5 run Workbench on the same host as Drupal, with a Drupal session.
  • In video 6, leaving the app's draft mode redirects to the app's front page, which this demo app does not have, so "Not found" flashes briefly.
  • Video 2's error and video 4's file edit are deliberate. Every change was reverted after recording.

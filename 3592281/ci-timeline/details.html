Method, sources and gaps in the evidence
  • Posted is the MR’s created_at (2026-11-03T11:05:12.935Z). Merged is its merged_at (2026-11-03T19:02:52.787Z). Approval is approved_at from the approvals API (2026-11-03T11:39:56.089Z, system note 11:39:56). Enabling auto-merge and marking the MR ready are separate events and are not counted as approval.
  • Queued is GitLab’s queued_duration, the time a job waited for a runner. Time spent waiting for earlier stages is not counted as queue. GitLab gives no pending timestamp, so where queue time sits on the timeline (and in the union arithmetic) is inferred as started_at − queued_duration → started_at.
  • Any job running is the length of the union of all attempts’ run intervals, so parallel jobs count once. Runner time adds up every attempt’s run time and so exceeds wall-clock. Over the MR’s life: 5 h 49 m 8 s running + 17 m 45 s only queued + 1 h 50 m 47 s with nothing queued or running = 7 h 57 m 40 s.
  • Retries are counted per pipeline and job as attempts minus 1, from the jobs API with include_retried=true. Each new pipeline came from a push (a test removal or a rebase), not from a rerun.
  • Not available from the provider: who or what decided each retry (the API records every attempt under balintbrews), how loaded the shared runner was, which tests were running when a job timed out, and the DrupalCode outage window (only the 502s in job 13337945’s log are evidence of it).

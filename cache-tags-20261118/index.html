Tag-based cache invalidation in Canvas Headless

How Drupal cache tags would let a frontend keep pages cached, then expire only the pages an edit affects.

01 — How it would work

Each cached page remembers what it depends on

Drupal already records cache tags for every page it renders, such as node:12 for an article. The response would carry those tags, and the frontend would store them with the cached page.

When an editor publishes, Drupal invalidates the affected tags. Canvas would send those tag names, not content, to the frontend in a signed request.

02 — Selective expiry

Only pages with a matching tag expire

Editing article 12 sends tags including node:12 and node_list. Here the frontend expires /news and /news/launch; /news/roadmap and /about stay cached.

/news carries a tag for each article it shows (node:9, node:12), plus node_list for membership: Drupal invalidates node_list whenever any node is saved, so a new article reaches the list. Views and JSON:API collections add these tags; a custom list must supply them, and the frontend must keep them.

node_list covers every content type, so any node save expires every cached page that carries it.

03 — Next request

The next visitor triggers the rebuild

Expiry rebuilds nothing by itself. A page is fetched again only when someone requests it:

  • Expire now: that visitor waits for Drupal.
  • Serve stale, refresh: that visitor gets the old copy at once while a fresh one loads in the background.

Pages nobody visits are never rebuilt. Browser tabs keep what they already loaded.

04 — Today in Canvas Verified · Canvas 3f8617f4 · 2026-11-18

What exists now

  • Drupal computes tags for every Canvas page response, but none reach the frontend. Core’s tag header is off by default, fetchPage() ignores response headers, and the JSON:API proxy drops tag headers.
  • The SDK fetches pages with no-store, and the Next.js template renders every page dynamically.
  • Nothing notifies a frontend when content changes.
  • Publishing saves each entity, so Drupal already invalidates the right tags.

What it would take

  • Tags on public page responses.
  • Adapters that cache page data under those tags.
  • A signed request to each configured frontend, sent after the publish commits.
  • A revalidation route in each adapter.

Open questions

  • Broad tags such as rendered and config:system.site would expire every page.
  • Data that code components fetch in the browser isn’t part of the page response.
  • Previews must never enter a shared cache.
05 — Framework support Official docs · 2026-11-18

Expiring by tag in each template’s framework

Next.js 16
Built in: cacheTag(), then revalidateTag(tag, 'max') to serve stale or { expire: 0 } to expire now.
Astro 7
Built in with a cache provider: Astro.cache.set({ tags }) and cache.invalidate({ tags }).
Nuxt 4, TanStack Start
No built-in tag expiry found; a CDN tag purge or a module.
Angular
The Canvas adapter sends private, no-store today.
